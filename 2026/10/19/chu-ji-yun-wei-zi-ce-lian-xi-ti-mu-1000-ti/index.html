把结果整理成一张简单的表格。

点击展开答案： 

printf "%-15s %-10s %-10s\n" "文件名" "ERROR数" "  总行数"
echo "------------------------------"
for log_path in "$HOME"/ops-lab/logs/*.log; do

    # -f：判断路径是否指向一个普通文件，不只是检查路径存在，还会排除目录等非普通文件

    [ -f "$log_path" ] || continue
    
    file=${log_path##*/}
    count=$(grep -c 'ERROR' "$log_path")
    total=$(wc -l < "$log_path")

    printf "%-15s %-10s %-10s\n" "$file" "$count" "$total"
done

“%-15s %-10s %-10s\n”
这些字符是 Linux 中 printf 命令的格式化占位符。它们的作用是“排版”，规整文本，让字串强制对齐，形成整齐表格。
把 %-15s 拆开来解释：
• %（启动符）：告诉系统，后面跟着的是一个排版指令，而不是要直接打印出来的普通文本。
• -（左对齐）：表示这一列的文字靠左对齐。如果不加减号 -，文字默认会靠右对齐。
• 15（列宽）：给这一列内容死死分配 15 个字符的宽度。
• 如果实际文本只有 5 个字符，系统会自动补 10 个空格。
• 如果实际文本超过了 15 个字符，它会原样输出，后面的内容会被往后推。
• s（数据类型）：代表 String（字符串）。告诉系统这里要填入的是一段文本。如果是数字，有时候会用 d。
• \n（换行符）：代表回车换行。printf 默认不会在末尾自动换行，必须手动加上 \n 才会换到下一行。

  1. 重要
    为 代码开发文件夹 src 设置正确权限
    即：开发团队共享源代码目录
    即：目录中新建的文件和子目录归 开发组 所有（要先把所有人加到开发组）
点击展开答案： 
# 是setgid 2
# 此特殊权限只影响组所有者。所有者仍然是创建文件的账户

sudo chmod 2770 ~/project/src

# 检查
ls -ld ~/project/src

输出：
drwxrws--- 2 username username 6 Oct 22 16:45 /home/project/src

# 权限中组执行位应显示为 s，类似 drwxrws---

举例，ls -l 里的显示：

2770 显示为 drwxrws—，属组的 x 位变成了 s
4755 显示为 -rwsr-xr-x，属主的 x 位变成 s
1777 显示为 drwxrwxrwt，其他人的 x 位变成 t（比如 /tmp）

如果 s 或 t 是大写（S、T），表示该位置原本没有 x 权限，只设置了特殊位。
有 x 又有特殊位 → 小写 s / t
没有 x 但有特殊位 → 大写 S / T

ls -l 的权限字段只有 9 个字符位置，没有给特殊位留空间。而 setuid/setgid 本来只对可执行文件有意义，所以设计者让它们叠加显示在 x 的位置上
特殊位是历史上为了解决具体问题后加的，所以排在最前面，并借用了 x 的显示位置

chmod g+s 目录 # 加 setgid
chmod u+s 文件 # 加 setuid
chmod +t 目录 # 加 sticky

位 主要用在 一句话
setuid 可执行文件 以文件属主身份运行
setgid 可执行文件 / 目录 以属组身份运行；目录里新文件继承属组
sticky 目录 只能删除自己的文件

sticky：
用在目录上，意思是”目录里的文件，只有文件的所有者（或目录所有者、root）才能删除或重命名”。
先理解背景：删除文件由谁决定
在 Linux 里，删除一个文件的权限不看文件本身，而看它所在的目录。只要你对目录有写权限（w），就可以删除目录里的任何文件，哪怕那个文件是别人的、你对它没有任何权限，为了解决文件乱删的问题，特意增加了sticky，只要文件夹有sticky，就只能删除自己的文件
举例，权限是 drwxrwxrwt，末尾的 t 就是 sticky

setuid:

= “set user ID”，意思是：程序运行时，以文件属主的身份运行，而不是以执行者自己的身份。
先理解背景：进程的身份
Linux 里每个运行中的程序（进程）都带着一个”身份”（用户 ID），系统根据这个身份判断它能访问什么。通常你运行一个程序，它就继承你的身份，只能做你能做的事
只对可执行文件有效，对普通脚本（shell 脚本）在多数系统上被忽略，出于安全考虑
设置方法：chmod u+s 文件 或 chmod 4755 文件
有安全风险：如果一个 root 属主的 setuid 程序有漏洞，攻击者就可能借它获得 root 权限。所以不要随便给程序加 setuid，系统里的 setuid 程序也应该尽量少
查看系统里有哪些 setuid 文件：find / -perm -4000 -type f 2>/dev/null

Cron 表达式常用频率对照表

频率 Cron 写法 含义说明
每毫秒 不支持 Cron 最小单位是分钟
每秒 不支持 Cron 本身不支持秒级调度
每分钟 * * * * * 每分钟运行一次
每小时 0 * * * * 每小时的第 0 分钟运行
每天 0 0 * * * 每天午夜运行
每周 0 0 * * 0 每周日午夜运行（星期字段中 0 通常表示周日）
每月 0 0 1 * * 每月运行一次（1号0点）
每年 0 0 1 1 * 每年运行一次（1月1号0点）

把 用户名 Linux 加入 newbie, sudo两个组

点击展开答案： 

sudo usermod -aG newbie, sudo Linux

如何查看系统中有哪些用户组？

点击展开答案： 

cat /etc/group
cut -d: -f1 /etc/group

# 从 /etc/group 文件的每一行中，只取出第一个字段，也就是组名
# cut：按指定规则截取文本字段
# -d:：指定字段分隔符是冒号 :
# -f1：只输出第 1 个字段
# /etc/group：要读取的文件；其中每行通常是冒号分隔的字段
